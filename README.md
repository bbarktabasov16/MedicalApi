# MedicalApi

Учебный Web API частной клиники на ASP.NET Core 9. Данные хранятся в статических списках, как в задании. База данных не используется.

## Запуск

```bash
dotnet run --launch-profile http
```

Swagger: http://localhost:5129/swagger/index.html  
OpenAPI: http://localhost:5129/openapi/v1.json

Порт 5129 использует HTTP. Для HTTPS запустите профиль `https` и откройте https://localhost:7061/swagger/index.html. Для локального HTTPS нужен сертификат разработки (`dotnet dev-certs https --trust`).

## Выполненные задания

1. Модели находятся в Models с namespace MedicalApi.Models. У пациента есть имя, дата рождения, телефон, адрес, номер квартиры и признак страховки.
2. Patients и Spravki поддерживают GET списка, GET по Id, POST, PUT и DELETE. PUT возвращает всю изменённую запись, сохраняя Id из адреса. DELETE возвращает 204 с пустым телом; повторное удаление — 404.
3. POST и PUT проверяют данные общим private-методом каждого контроллера. Ошибки возвращаются как 400 с понятным текстом. Ошибки JSON также возвращаются текстом.
4. Справка связана с пациентом через PatientId. GET /api/Patients/{id}/spravki возвращает справки пациента, пустой список, если справок нет, или 404, если пациента нет.
5. Каталог SpravkaTypes содержит CRUD и четыре начальных вида. Два своих вида: справка для занятий танцами и справка для участия в школьной экскурсии. Дополнительные поля: ValidDays, RequiresExamination, ForChildren.
6. Собственный модуль: Doctors — картотека врачей, CRUD, имя, специальность, кабинет и признак доступности.
7. Собственные решения и улучшения: запрет удаления пациента со справками, защита используемого вида справки от удаления, тестовые данные и статистика.
8. Исправлены повторяющиеся Id и описание кодов ответов Swagger через ProducesResponseType.

Пункты 6–8: собственный модуль — картотека врачей (Models/Doctor.cs, DoctorsController, /api/Doctors). Он поддерживает GET, POST, PUT, DELETE и проверки данных. Модуль самостоятельный: связь врача с пациентами и справками не вводится. Улучшения — статистика, тестовые данные и правила удаления связанных записей. В каждом модуле исправлена выдача Id и указаны реальные коды ответов для Swagger.

## Правила

- Имя пациента: минимум два символа после удаления пробелов по краям; дата рождения обязательна и не может быть в будущем; номер квартиры неотрицательный.
- Вид справки: непустое название, положительные цена и срок действия.
- Справка: пациент и вид должны существовать. Name и Price всегда берутся из каталога при POST и PUT; присланные клиентом значения игнорируются.
- Врач: непустые имя и специальность, положительный номер кабинета.
- Пациента со справками удалить нельзя: 400 с объяснением. Сначала нужно удалить его справки.
- Вид, по которому есть справки, удалить нельзя: 400 с объяснением.
- Изменение каталога не меняет уже выданные справки. При следующем PUT справки значения снова берутся из текущего каталога.
- Id назначается сервером счётчиком, который не уменьшается после удаления. Это действует во всех четырёх модулях.
- Изменения хранятся только до перезапуска. При запуске восстанавливаются четыре вида, три пациента, три справки и два врача. Добавленные через API виды тоже сбрасываются: постоянное хранение не входит в задание.

## Показ в Swagger

1. GET /api/SpravkaTypes — четыре вида сразу после запуска.
2. POST /api/Patients с именем и датой рождения; проверить 201 и заголовок Location.
3. POST /api/Spravki с полученным PatientId, SpravkaTypeId = 3 и произвольной ценой. В ответе название из каталога и цена 400.
4. Создать вторую справку тому же пациенту, открыть GET /api/Patients/{id}/spravki.
5. PUT пациента: проверить 200, полную запись и сохранение Id.
6. Отправить отрицательную цену в каталог, пустое имя пациента, будущую дату рождения, несуществующие PatientId и SpravkaTypeId: получить 400.
7. Удалить пациента со справками: 400. Удалить справки: 204. Удалить пациента: 204. Повторить удаление: 404.
8. В Doctors показать создание, редактирование и удаление врача.
9. GET /api/Spravki/statistics — Count и TotalAmount по всем текущим справкам.
10. Создать три записи, удалить среднюю, создать четвёртую: Id различаются. Проверить это во всех модулях.
11. В Swagger раскрыть Responses у POST и DELETE: 201/400 и 204/400/404 соответственно.

## Эксперименты с JSON

- Неизвестное поле игнорируется.
- Число вместо строкового имени: 400.
- Пустое тело, повреждённый JSON или null вместо объекта: 400.
- Дата "15.05.2000": 400. Используйте "2000-05-15".
- Отсутствующий Id в GET/PUT/DELETE: 404.
- PUT несуществующей записи не создаёт новую.
